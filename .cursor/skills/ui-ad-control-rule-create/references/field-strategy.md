# 字段策略

## 优先级

```text
用户明确值
→ 当前页面已有值
→ verified 且标记为宽泛的知识默认值（仅必填空字段）
→ 阻断并询问用户
```

- 管控维度、业务线、至少一个指标是请求必填项；渠道仅在用户明确指定时填写。
- 项目在页面或业务上下文要求时必填；无法从页面确定时询问用户。
- 用户明确填写的管控维度、投放版本、投放方式、媒体、转化目标等必须逐项保留。
- `unknown` 知识不能自动填写，也不能通过通用确认绕过。
- “不限”只有在知识明确证明其为该字段的宽泛值时才可作为默认值。
- 页面不存在用户明确字段或不存在精确选项时阻断，不进行模糊猜测。

## 动态页面

- 选择上游字段后等待联动，再重新扫描可见 `.el-form-item`。
- 联动完成以连续三次字段快照一致为准，不使用固定字段数量；快照至少包含标签、控件类型、必填状态和当前值状态。
- 补默认值采用循环：扫描 → 填一个必填空字段 → 等待联动 → 重新扫描，直到无可补字段。
- 用可见标签绑定控件，兼容 input、textarea、radio、select 和 el-select-v2。
- el-select/el-select-v2 只读取当前控件 `aria-controls` 指向的 listbox；虚拟列表有限遍历并在选择后回读。
- radio/checkbox 优先操作语义控件，隐藏 input 不响应时点击可见 label，并验证最终选中状态。
- 必填判断以页面星号/校验状态和 verified 知识共同决定。
- 条件行按请求长度增加，逐行填写时间范围、聚合方式、指标、比较符和值。
- 提交前回读所有用户字段和条件；任何差异都阻止提交。

## 联动表单与复合控件的通用处理

不要为“主体”“业务线”或某个具体选项增加字段名特判。所有联动字段和复合下拉统一执行：

```text
选择上游字段
→ 等待可见字段快照稳定
→ 按标签重新定位字段容器
→ 优先选择具有该标签可访问名称的交互控件
→ 只在该控件 aria-controls 指向的可见选项面板中精确匹配
→ 选择后同时回读控件值、选中标签和字段非空状态
→ 再次等待联动稳定并重新扫描表单
```

- 一个字段容器包含多个 `combobox` 时，禁止使用 `.first()` 猜测。优先选择 accessible name 与字段标签匹配的控件；无法唯一定位时以 `UI_CONTROL_AMBIGUOUS` 阻断。
- 页面可能保留隐藏的旧下拉面板和重复选项。只允许点击当前控件所控制的可见 listbox；禁止从全局 option 集合选择。
- 虚拟列表尚未渲染目标项时，只在当前控件中有限次数键盘遍历；仍找不到时输出已发现选项并阻断。
- 点击成功不代表填写成功。至少验证以下两类信号：控件值或选中标签等于期望值；字段快照由空变为非空。任一不一致均报 `UI_FIELD_READBACK_MISMATCH`。
- radio/checkbox 的原生 input 可能隐藏。语义操作失败时点击对应的可见 label，并以 checked/选中样式回读，不能仅凭点击无异常判定成功。
- 弹窗按 `dialog` 角色和关键表单控件定位，不依赖固定 CSS 层级；列表页和弹窗存在相似输入框时必须限制在 dialog 作用域内。
- 每次填写都应是可独立验证的原子步骤。失败日志至少包含字段标签、期望值、控件数量、当前可见选项和回读值，便于判断是联动未完成、定位歧义还是选项不存在。
